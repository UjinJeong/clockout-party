# 자동 움직임: 단어 프롬프트 + 붓으로 고치기 — 설계

상태: 승인됨 (2026-11-27, 사용자: "A+C가 좋은거 같아")
앞선 설계: 2026-11-27-auto-motion-design.md (자동 분석)

## 왜
자동 분석은 그림 속에 무엇이 있는지 모른다(회색 하늘은 하늘로 못 봄, 꽃잎이 날렸으면 하는 마음도 모름).
그림을 그린 사람이 **짧은 단어**로 방향을 주고, **붓으로 직접** 움직일 곳을 고칠 수 있게 한다.

## 방법 (고려한 것)
- A. 단어 프롬프트(정해진 단어 사전, AI 없음) ← 선택
- B. 글로 위치 찾기 AI(CLIPSeg) — 무겁고 영역이 뭉툭, 결국 붓으로 고치게 됨. 제외
- C. 붓으로 칠하기 ← 선택 (A와 함께)

## 무엇을
### A. 단어 프롬프트
- 그림 칸의 🪄 자동 움직임 상자에 한 줄 입력(60자). 예: "회색 하늘, 바다, 꽃잎 날림".
- 알아듣는 말(띄어쓰기·조사 무관, 단어 앞부분으로 맞춤):
  - 하늘·구름·노을 → 위쪽 매끈한 곳을 **색과 상관없이** 흐름으로
  - 바다·물·강·호수·연못·파도 → 아래쪽 매끈한 곳을 색과 상관없이 물결로
  - 바람·잎·풀·나무·숲·털 → 살랑임(잔결 기준을 낮춰 더 넓게)
  - 반짝·빛·별·금·윤슬 → 반짝임
  - 입체·깊이 → 입체
  - 고요·정지·"움직임 없이" → 아무것도 움직이지 않음
  - **날리는 것**(새 기능, 그림 위에 얹는 효과): 꽃잎·벚꽃 → 꽃잎, 눈송이·함박눈·"눈 내림" → 눈, 반딧불 → 반딧불, 빗방울·"비 내림" → 비
- 말한 효과는 최소 넓이 기준을 낮춰서라도 켠다(작가가 원한 것이므로).
- 알아들은 말을 칩으로 보여 준다. 날리는 것은 따로 고를 수도 있다(없음/꽃잎/눈/반딧불/비).
- 프롬프트는 그림과 함께 저장(다시 읽을 때 그대로 씀).

### C. 붓으로 고치기
- 미리보기 위에 붓: 🌊 흐름 / 🌿 살랑임 / ✨ 반짝임 / 🧽 지우개, 굵기 3단계.
- 칠한 결과로 넓이·효과를 다시 계산(칠한 곳은 작아도 켬), 움직임 지도 PNG를 다시 만든다.
- 분석이 "움직일 곳 없음"이어도 붓으로 칠하면 움직인다.

## 저장
- gallery.json 항목: `prompt`(≤60자), `drift`('petals'|'snow'|'fireflies'|'rain'), 기존 mask·depth·fx. 바꾼 그림에만.

## 뷰어
- 바꾼 그림에 `drift`가 있으면 그림 위로 꽃잎/눈/반딧불/비가 날린다(기존 반딧불 효과 재사용 + 새 효과 3종).

## 하지 않을 것
- 문장 이해(AI 없음), 그림 속 물체를 오려 내 따로 움직이기.

## 빌더 판단
- 단어 사전 내용, 프롬프트가 켠 효과의 최소 넓이(2%), 붓으로 칠한 효과의 최소 넓이(0.2%), 붓 굵기.

## 구현 결과 (2026-11-27)
- `autoMotion.js`: `parsePrompt`(단어 사전, 조사 허용, 한 글자 단어는 다른 낱말 속에서 안 맞춤: 동물≠물, 비율≠비, "큰 눈"≠눈 내림), `analyze(..., hints)`, `brush`, `areasOf`, `MANUAL_AREA`·`PROMPT_AREA`, `howFor(found, drift)`.
- 관리자 화면: 단어 입력 + "이 말로 다시 읽기", 알아들은 말 칩, 미리보기 위 붓(흐름·살랑임·반짝임·지우개, 굵기 3단계), 날리는 것 선택. 원래 그림으로 되돌리면 단어·날리는 것도 지움.
- 뷰어: 바꾼 그림의 `drift` → 꽃잎(그림 밖까지 흩날림)·눈·비(액자 안)·반딧불(기존 효과).
- 확인: 해바라기 그림에서 "회색 하늘, 꽃잎 날림" → 흐린 하늘 흐름 0%→25%, 꽃잎 선택, 붓질로 반짝임 6.5%→27.5%, 저장 내용에 prompt·drift·fx·지도 파일 포함, 뷰어에서 꽃잎·눈·비 확인. 테스트 588개 통과.
