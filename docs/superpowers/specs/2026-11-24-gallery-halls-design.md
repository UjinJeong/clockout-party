# 전시장 관 관리 — 설계

2026-11-24 · 상태: 검토 대기

## 왜 만드나

전시장의 관은 그림 분위기의 묶음이다(정원관 = 바람·꽃, 연못관 = 물·물고기). 새 그림이 들어왔는데 어느 관의 분위기와도 맞지 않으면 지금은 걸 곳이 없다. 관리자(정유진)가 관리자 페이지에서 직접

- 그 그림에 맞는 새 관을 만들고,
- 기존 관의 이름·분위기를 다듬고,
- 관마다 걸 그림 수를 늘리거나 줄일 수 있어야 한다.

그림 교체·설명 수정(전시장 탭, 2026-11-23)과 같은 흐름으로, 누가 부탁하면 코드를 고치지 않고 처리할 수 있게 한다.

## 목표

- 관리자 페이지에서 관을 추가·삭제·이름 변경·순서 변경할 수 있다.
- 관마다 분위기(이름, 벽 색, 소개 한 줄)를 정할 수 있다.
- 관에 거는 그림 수에 맞춰 3D 건물(관의 폭, 그림 자리, 벤치, 화분, 조명, 관 이름표)이 자동으로 지어진다.
- 서버와 화면, 체험판이 같은 관 목록으로 같은 건물을 짓는다(서버는 벽 통과를 막는 데 쓴다).

## 하지 않는 것

- 관마다 바닥·조명·장식을 다르게 꾸미기. 분위기는 이름·벽 색·소개 한 줄로만 정한다.
- 저장하는 순간 열린 파티에 바로 반영하기. 그림 교체처럼 저장 → GitHub → 재배포(2~5분)로 반영한다.
- 관 가운데 양면 벽(방법 C). 관이 많아져 건물이 너무 길어지면 그때 따로 다룬다.
- 홈파티·풀파티 맵 변경.

## 실패로 보는 것 (기능은 돌아가도)

- 관을 바꾼 뒤 걷다가 벽에 끼이거나 벽을 통과한다(서버와 화면의 건물 모양이 다르다).
- 관을 지웠더니 그 관의 그림이 말없이 사라진다.
- 지금 있는 4개 관이 이전과 눈에 띄게 다르게 보인다(연못관 폭 변경은 예외로 미리 알림).
- 저장한 관 목록이 깨져서 서버가 켜지지 않는다.

## 제약

- 무료 Render 서버, GitHub 저장, 자동 재배포 구조는 그대로 둔다.
- 서버는 `shared`의 맵으로 이동·충돌을 검사한다. 관 목록이 서버와 화면에 똑같이 들어가야 한다.
- 체험판(아티팩트)은 같은 빌드에서 나오므로 관 목록도 함께 들어간다. 다만 관리자 페이지 저장만으로는 체험판이 바뀌지 않는다(지금과 같음).
- 나중에 Unity 클라이언트가 같은 서버에 붙는다. 건물을 짓는 규칙은 화면 코드가 아니라 `shared`에 둔다.

## 방법 (검토한 것과 고른 것)

### 한 관에 그림이 많을 때

| 방법 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A (선택)** | 관마다 최대 8점. 5점까지 폭 12m, 6~8점 15m. 넘치면 같은 분위기의 "Ⅱ관"을 만든다 | 관이 적당한 크기로 유지되고 걷기 편함. "관 = 분위기"와 잘 맞음 | 같은 분위기가 두 관으로 나뉨 |
| B | 제한 없이 관이 넓어짐 | 한 분위기가 한 관에 다 모임 | 20점이면 관 하나가 40m. 휴대폰에서 지루하고 벤치·조명 간격이 어색함 |
| C | 관 가운데 양면 벽으로 최대 12점 | 미술관 같은 느낌, 건물이 안 길어짐 | 만들 게 가장 많음. 방이 좁아짐 |

정유진이 A를 골랐다.

### 관 목록을 어디에 두고 언제 반영하나

| 방법 | 내용 | 판단 |
| --- | --- | --- |
| **목록 파일 + 재배포 (선택)** | 관 목록을 그림 목록과 같은 파일에 넣는다. 서버·화면이 빌드 때 읽는다 | 그림 교체와 같은 흐름. 파티 중에 건물이 바뀌지 않아 안전. 체험판에도 들어감 |
| 실행 중 반영 | 서버가 저장하는 순간 관 목록을 바꾸고 화면이 받아서 다시 짓는다 | 파티 중 건물이 바뀌어 서 있던 사람이 벽에 갇힐 수 있음. 체험판에 반영 안 됨. 버림 |

## 설계

### 1. 데이터: 전시장 파일 하나

`client/src/world/gallery.json`을 `shared/src/gallery.json`으로 옮기고 모양을 바꾼다.

```json
{
  "halls": [
    { "id": "garden", "name": "정원관", "color": "moss", "note": "바람과 숨결이 지나가는 방. 꽃과 나비, 씨앗이 액자 밖으로 날아갑니다." },
    { "id": "face", "name": "얼굴관", "color": "crimson", "note": "…" }
  ],
  "items": [ { "i": 17, "room": "garden", "title": "민들레와 발", "…": "…" } ]
}
```

- `halls`의 순서가 건물의 관 순서다. 로비는 목록에 없고 항상 맨 앞이다.
- `id`: 새 관은 `h` + 무작위 6자(예: `h3k9x2a`). 그림의 `room`이 이 값을 가리킨다. 이름을 바꿔도 `id`는 그대로라 그림 연결이 끊기지 않는다.
- `color`: 정해 둔 벽 색 8가지 중 하나의 이름(`HALL_COLORS`). 지금 4색(moss `#4a5a43`, crimson `#6b2727`, navy `#28324f`, teal `#22434a`)과 새 4색(어울리는 짙은 톤: plum, ochre, slate, umber)이다.
- `note`: 소개 한 줄(최대 80자). 관 입구 이름표 아래와 살아난 그림 화면의 관 소개에 쓴다. 지금 두 군데(art.ts의 짧은 글, viewer.js의 긴 글)에 나뉜 소개는 viewer.js의 긴 글 하나로 합친다.
- 그림 하나에 붙는 정보와 규칙(제목, 설명, 도슨트 답 등)은 바꾸지 않는다.

`checkGallery`가 관까지 검사한다.

- 관 1~12개, `id` 겹치지 않음, 이름 1~12자, `color`는 목록 안의 값, `note` 80자 이하.
- 모든 그림의 `room`이 있는 관을 가리킨다.
- 관마다 걸린(숨기지 않은) 그림 0~8점.
- 걸린 그림이 0점인 관도 허용한다(새 관을 만들고 그림을 옮기기 전 단계). 화면에서는 빈 벽 대신 "곧 그림이 걸릴 방이에요" 이름표만 보인다.

### 2. 건물 짓기 규칙 (`shared`)

`buildGalleryMap(halls, counts)`가 관 목록과 관마다 걸린 그림 수로 `WorldMap`과 그림 자리를 만든다. 서버, 화면, 체험판이 이 함수 하나를 쓴다.

```
x = 0        로비 (폭 12m, 지금과 같음)
x = 12       1관 (폭 12m 또는 15m)
x = 12+폭    2관 …
끝           마지막 관 끝 벽
```

- 관의 폭: 걸린 그림 5점 이하 12m, 6~8점 15m.
- 칸막이 벽: 관과 관 사이마다 문(폭 4m)이 있는 벽. 지금 `partition()`과 같다.
- 그림 자리(관 안의 칸 순서): 뒷벽에 먼저, 남으면 옆벽에 건다. 지금 관들이 그렇게 생겼다.

| 걸린 그림 | 폭 | 뒷벽 | 왼쪽 벽 | 오른쪽 벽 (칸막이 또는 끝 벽) |
| --- | --- | --- | --- | --- |
| 0 | 12m | - | - | - |
| 1~3 | 12m | 1~3점 (3점이면 2.4 / 6 / 9.6m, 1점이면 가운데) | - | - |
| 4 | 12m | 3 | 1 | - |
| 5 | 12m | 3 | 1 | 1 |
| 6 | 15m | 4 | 1 | 1 |
| 7 | 15m | 5 | 1 | 1 |
| 8 | 15m | 6 | 1 | 1 |

뒷벽 자리는 관 폭을 고르게 나눈다(15m에 6점이면 2.5m 간격). 자리가 촘촘하면 그림 최대 폭(maxW)을 그 간격에 맞춰 줄인다. 1~5점은 지금 관들의 자리와 같다.

- 벤치: 관 가운데 하나(지금과 같음). 폭 15m 관도 하나.
- 서 있는 탁자: 관 양끝 앞쪽(지금과 같음).
- 화분: 옆벽에 그림이 없는 관 구석에만(지금 규칙과 같음).
- 봇이 서는 자리(spots): 그림마다 그 앞.
- 천장 전구 줄, 바닥 러너, 카메라가 움직이는 범위: 건물 전체 길이를 따른다.

연못관은 지금 7점이라 폭이 12m에서 15m로 넓어진다. 이 외의 3개 관은 같은 규칙으로 지금과 같은 위치에 지어져야 한다(테스트로 확인).

### 3. 화면

- `RoomId` 같은 고정된 관 이름 목록을 없애고 `halls`를 읽는다.
- 벽 천, 관 이름표, 그림 액자, 벤치, 전구 줄, 살아 있는 벽(livingWall)이 `buildGalleryMap`의 결과를 따라 지어진다.
- 살아난 그림 화면(viewer.js)의 관 목록과 관 소개가 `halls`를 읽는다. 원래 그림의 손으로 만든 움직임은 그대로다.
- 휴대폰에서 건물이 길어지면 카메라 범위만 늘어난다. 미니맵은 없으므로 따로 바꿀 것이 없다.

### 4. 관리자 페이지 (전시장 탭 위쪽 "관" 칸)

```
🏛️ 관                                         [+ 새 관]
┌─────────────────────────────────────────────────────┐
│ ■ 정원관   5 / 8점   [↑][↓] [고치기] [지우기(흐림)]  │
│ ■ 얼굴관   4 / 8점   …                              │
│ ■ 연못관   8 / 8점   [Ⅱ관 만들기] …                 │
└─────────────────────────────────────────────────────┘
고치기: 이름 · 벽 색(8색 동그라미) · 소개 한 줄
```

- 관 순서 ↑↓, 고치기(이름·벽 색·소개), 새 관, 지우기.
- **지우기는 그 관에 그림이 0점일 때만** 된다(숨긴 그림 포함). 아니면 "그림 N점을 다른 관으로 옮기거나 내린 뒤 지울 수 있어요"라고 안내한다.
- 꽉 찬 관(8/8)에는 "Ⅱ관 만들기"를 보여 준다. 이름 뒤에 Ⅱ(이미 있으면 Ⅲ…)를 붙이고 색·소개를 복사해 바로 뒤에 만든다.
- 그림 고치기의 "전시실" 칸은 관 목록에서 고른다. 꽉 찬 관은 고를 수 없게 흐리게 보인다.
- 저장은 지금 저장 막대를 그대로 쓴다. 관 변경도 "바뀐 것" 개수에 들어가고, 한 번에 한 커밋으로 저장된다.
- 저장 기록 이름에 관 변경을 적는다(예: `Gallery: 새 관 "바다관", 연못관 이름 변경`).

### 5. 안전장치

- 서버가 켜질 때 `checkGallery`가 실패하면(손으로 파일을 잘못 고친 경우 등) 마지막으로 맞았던 기본 관 4개로 짓고 로그에 남긴다. 서버가 아예 안 켜지는 일은 없게 한다.
- 저장 API는 지금처럼 `checkGallery`를 통과한 것만 GitHub에 올린다.
- 저장된 그림·관 파일 형식이 바뀌므로, 옛 형식(배열만 있는 파일)도 읽어서 기본 관 4개를 붙인 새 형식으로 바꿔 준다(배포 직후 GitHub에 남아 있는 옛 파일 대비).
- 파일 위치가 `client/src/world/gallery.json` → `shared/src/gallery.json`으로 바뀐다. 저장 코드(`galleryStore`)의 경로도 같은 커밋에서 바꾼다. 옮기는 배포 전에 관리자 페이지에서 저장해 둔 내용은 옮길 때 그대로 가져간다.

## 테스트

- **shared:** `buildGalleryMap`
  - 지금 4개 관(5·4·3·7점)으로 지었을 때 정원·얼굴·장난감관의 벽·그림 자리·벤치·화분이 지금 값과 같다.
  - 관 1개~12개, 관마다 0~8점의 모든 조합에서 그림 자리가 서로 겹치지 않고, 벽 안쪽에 있고, 그림 앞에 서는 자리가 걸어갈 수 있는 곳이다.
  - 로비에서 마지막 관 끝까지 길찾기가 된다.
- **shared:** `checkGallery`의 관 규칙(겹치는 id, 없는 관을 가리키는 그림, 9점 관, 옛 형식 읽기).
- **server:** 관을 바꾼 파일로 방을 열었을 때 새 관 안을 걸을 수 있고 벽은 막힌다. 저장 API가 관 변경을 한 커밋으로 올린다(가짜 GitHub).
- **화면:** 관 6개·8점짜리 관을 넣은 빌드를 Playwright로 열어 PC·휴대폰 크기에서 끝까지 걸어 보고 캡처한다. 지금 4개 관 빌드는 이전 캡처와 비교한다.
- **관리자 페이지:** Playwright로 새 관 → 그림 옮기기 → Ⅱ관 만들기 → 빈 관 지우기 → 저장(가짜 GitHub)까지.

## 진행 순서

1. 관 정보를 `halls`로 모으기. 겉모습 변화 없음, 모든 테스트 통과.
2. `buildGalleryMap`으로 건물 자동 짓기. 지금 4개 관 비교 + 큰 관 목록으로 걷기 확인.
3. 관리자 페이지 "관" 칸.
4. 배포. 정유진이 직접 저장해 보고 PC·휴대폰에서 걸어 보기. 체험판 다시 올리기.

## 만드는 사람이 정할 것

- 새 4가지 벽 색의 정확한 값(전시장 조명 아래에서 캡처를 보고 고른다).
- 8점 관의 그림 간격과 최대 크기.
- "곧 그림이 걸릴 방이에요" 이름표의 모양.

## 내가 정한 것 (정유진 확인 필요)

- 칸 수를 따로 정하지 않고, 걸린 그림 수에 맞춰 벽이 지어진다(최대 8점).
- 관 분위기는 이름 + 벽 색(8색 중 선택) + 소개 한 줄.
- 관은 최대 12개.
- 그림이 0점인 관도 저장할 수 있다.
- 로비는 항상 맨 앞이고 고칠 수 없다.
- 연못관은 7점이라 폭이 15m로 넓어진다.
