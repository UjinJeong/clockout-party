# 방명록·좋아요 남기기 — 설계

2026-11-27 · 상태: 승인됨 (정유진, A안)

## 왜

방명록 글과 그림 좋아요가 서버 메모리에만 있어서, 다시 배포하거나 무료 서버가 잠들면 사라진다. 게다가 방마다 따로 있어서 방이 닫히면 같이 사라진다. 다음에 온 사람이 앞사람의 흔적을 봐야 다시 들어올 이유가 생긴다.

## 방법

| 방법 | 판단 |
| --- | --- |
| **A. Render Key Value(무료) (선택)** | Render 안에서 해결되고 글이 공개되지 않는다. 무료라 디스크 백업은 없다 |
| B. GitHub 저장소 | 저장소가 공개라 글과 이름이 영원히 공개된다. 버림 |
| C. 외부 DB | 새 계정이 필요하다. 버림 |

## 설계

- **어디에 모이나 (내가 정한 것):**
  - 공개 방의 방명록은 **테마마다 하나**다. 오늘 연 전시장 파티든 내일 연 전시장 파티든 같은 벽을 본다. 최근 30개를 남긴다.
  - **친구만 방(비공개)은 지금처럼 그 방 안에서만** 보이고 저장하지 않는다. 친구끼리 쓴 글이 모르는 사람에게 보이면 안 되기 때문이다.
  - 좋아요는 그림마다 숫자라서 공개·비공개 방 모두 합쳐서 저장한다.
- **한 사람 한 번:** 좋아요는 브라우저마다 만든 방문자 키(localStorage)의 해시로 센다. 다시 들어와도 같은 사람이 두 번 누르지 못하고, 다시 누르면 취소된다. 키가 없으면(옛 화면 등) 접속 번호로 센다.
- **실시간:** 한 방에서 쓴 글·좋아요는 같은 테마의 열린 공개 방 모두에 바로 보인다.
- **저장소:** `REDIS_URL`이 있으면 Key Value에 저장한다. 없으면(개발, 테스트, 연결 실패) 지금처럼 메모리만 쓴다. 저장이 실패해도 파티는 멈추지 않고, 로그에 한 번 남긴다.
  - `party:notes:{theme}`: 최근 30개 목록
  - `party:likes:{theme}:{art}`: 좋아요한 방문자 집합, `party:likes:{theme}`: 좋아요가 있는 그림 목록
- **Render:** `render.yaml`에 무료 Key Value(`clockout-party-kv`, 싱가포르, 외부 접속 없음)를 추가하고 `REDIS_URL`로 연결한다. 정유진이 Render에서 Blueprint 변경을 승인한다.

## 테스트

- 저장소: 진짜 Redis(로컬 redis-server)와 메모리 둘 다 같은 테스트로 — 글 30개 넘으면 오래된 것부터 빠짐, 좋아요 켜고 끄기, 다시 불러오기.
- 서버: 공개 방 두 개가 방명록을 같이 본다 / 비공개 방 글은 다른 방에 안 보인다 / 같은 방문자 키로 다시 들어와 좋아요를 누르면 취소된다 / 서버를 "다시 켜도"(저장소에서 다시 불러와도) 글과 좋아요가 남는다 / 저장소가 고장 나도 글은 방에 보인다.
