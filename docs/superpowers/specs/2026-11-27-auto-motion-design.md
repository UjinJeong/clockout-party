# 새 그림 자동 움직임 — 설계

상태: 승인됨 (2026-11-27, 사용자: "그렇게 만들어줘, 분석이 안 되면 그냥 움직임 없이 올리는 거고")

## 왜

관리자 페이지에서 그림을 바꾸거나 새로 걸면, "살아난 그림" 화면에서 손으로 만든 전용 효과(나비, 잉어 등)가 꺼지고 빛이 은은하게 스치는 효과만 남는다. 그림을 올릴 때 그림을 분석해서 그 그림에 맞는 움직임을 자동으로 만들어 주고 싶다. 코드 작업 없이 관리자 페이지만으로 새 그림도 살아 움직이게 하는 것이 목표.

## 목표 / 하지 않을 것 / 실패로 보는 것

- 목표
  - 그림을 올리면(교체·새로 걸기) 관리자 브라우저에서 자동으로 분석해 **움직임 지도**(mask)와 **깊이 지도**(depth), **효과 세기**(fx)를 만든다.
  - 결과를 관리자가 보고 효과별로 끄기·세기 조절을 한 뒤 저장한다.
  - 저장하면 그림 파일과 함께 GitHub에 커밋되고, 살아난 그림 뷰어가 그대로 쓴다.
  - 이미 걸려 있는 교체된 그림에도 "🪄 움직임 자동 만들기"로 나중에 만들 수 있다.
- 하지 않을 것
  - 그림 속 물체를 알아보고 따로 움직이기(나비가 액자 밖으로 날기 등). 원래 그림 19점의 손으로 만든 효과는 그대로 둔다.
  - 파티장 3D 벽의 움직임은 지금처럼 관의 움직임(바람·숨결·반짝임·물결·고요)을 따른다.
  - 서버에서 분석하지 않는다. Claude나 유료 API를 부르지 않는다.
- 실패로 보는 것
  - 분석 때문에 그림을 못 올리는 것. 분석이 실패하거나 아무것도 못 찾으면 **움직임 없이** 올라가야 한다.
  - 그림이 일그러져 보일 만큼 과한 움직임. 기본값은 약하게.

## 방법 (고려한 것)

1. **색·질감 분석만 (AI 없음)** — 가볍고 즉시. 입체감은 없음.
2. **색·질감 분석 + 깊이 AI (브라우저에서 실행)** — 앞뒤 입체 들썩임까지. 처음 한 번 모델 파일(약 25MB)을 받음. ← **선택됨**
3. 영상 생성 AI — 진짜 움직이지만 유료·상호작용 없음·그림체 변형 위험. 제외.

## 어떻게

### 분석 (관리자 브라우저, `server/src/autoMotion.js` — 순수 함수 모듈)

- 입력: 줄인 그림 픽셀(긴 변 ~160px), 선택적으로 깊이 AI 결과.
- 움직임 지도(RGB, 뷰어의 기존 약속 그대로):
  - **R = 흐름**(하늘·물): 위쪽에서 이어지는 밝고 매끈한 파랑·하늘색 영역(하늘), 아래쪽의 매끈한 파랑·청록 영역(물). 누르면 파문도 R 안에서만.
  - **G = 살랑임**(잎·풀·털): 잔무늬가 많은(국소 분산·경계 밀도가 높은) 영역, 초록 계열에 가중치.
  - **B = 반짝임**: 아주 밝은 하이라이트, 금빛(채도 높은 노랑) 점.
  - 지도는 부드럽게 흐리게 처리해 경계가 튀지 않게 한다.
- 효과 세기 fx: 영역 넓이에 따라 `flow`, `sway`, `shimmer`, `ripMask` 등을 정한다(기본은 약하게). 영역이 너무 작으면(예: 6% 미만) 그 효과는 0.
- 깊이 AI: transformers.js(CDN, 버전 고정) + `onnx-community/depth-anything-v2-small`(양자화). 가까울수록 밝게, 0~1로 정규화. 실패하면 깊이 없이(평평) 진행.
- 아무 효과도 없으면 → 움직임 없음.
- "해 보기"·힌트가 비어 있으면 찾은 효과로 문구를 만들어 채운다(템플릿, AI 아님).

### 저장

- 파일: `gallery/<i>-<tag>-m.png`(움직임 지도), `gallery/<i>-<tag>-d.png`(깊이 지도), 그림과 같은 폴더·같은 커밋.
- gallery.json 항목에 `mask`, `depth`(경로), `fx`(숫자 몇 개) 추가.
- `checkGallery`가 경로와 fx 키·범위를 검사한다(허용 키만, 범위 밖은 잘라냄). `fx: {}`는 "움직임 없음".
- 저장소가 커밋할 파일 목록(`used`)에 mask·depth 포함.

### 뷰어 (`client/src/living/viewer.js`)

- 교체·새 그림: `fx`가 있으면 그 mask·depth·fx로 움직인다. `fx`가 비어 있으면 움직임 없음. `fx`가 없으면(이 기능 이전 그림) 지금처럼 은은한 반짝임.
- 원래 그림 19점: 변화 없음.

### 관리자 화면

- 그림을 고르면: "🪄 움직임 분석 중…(처음엔 AI 모델을 받느라 30초쯤)" → 결과 칩 `🌊 흐름 n% · 🌿 살랑임 n% · ✨ 반짝임 n% · 🧊 입체`. 각 효과 끄기/약/보통/강. 지도 미리보기(색 덧칠). 실패·없음 → "움직임 없이 걸어요".
- 교체된 그림 칸에 "🪄 움직임 자동 만들기 / 다시 만들기" 버튼.

## 제약

- 관리자 페이지는 빌드 없는 일반 JS. 분석 모듈은 `/admin/auto-motion.js`로(관리자 전용) 내려준다.
- 모델 파일은 관리자 브라우저만 받는다. 방문자는 작은 PNG 두 장만 받는다.
- 기존 테스트 전부 통과, 새 순수 함수는 단위 테스트.

## 빌더에게 맡긴 것 (내 판단)

- 영역 판정 문턱값과 효과 세기 기본값.
- 깊이 AI 모델 크기/양자화 선택(브라우저 호환 우선).
- 미리보기 모양.

## 구현 결과 (2026-11-27)

- `server/src/autoMotion.js`: 분석(analyze), 세기(fxFor), 문구(howFor / isAutoHow), 부드럽게 줄이기(shrinkTo). 관리자 전용 `/admin/auto-motion.js`로 내려줌.
- 판정 규칙(빌더 판단):
  - 하늘 = 위쪽 가장자리에 닿는 매끈한 파랑·하늘색(또는 채도 높은 노을색). 베이지 종이는 제외.
  - 물 = 아래쪽 가장자리에 닿는 파랑·청록·짙은 남색. 물 안의 반영(양옆이 물인 곳)도 함께 흐르고, 수면 위쪽은 서서히 시작.
  - 살랑임 = 주변에 잔 경계가 빽빽한 곳(잎·풀·털). 윤곽선 하나는 제외.
  - 반짝임 = 주변보다 확 밝은 점, 붓결이 있는 금빛. 평평한 노란 벽은 제외.
  - 최소 넓이: 흐름 8%, 살랑임 8%, 반짝임 0.3%. 기본 세기는 "보통"(약하게 0.6배, 강하게 1.6배).
- 깊이 AI: transformers.js 3.7.1(jsDelivr) + depth-anything-v2-small. WebGPU가 있으면 GPU, 없으면 q8로 CPU(WASM). 관리자 브라우저에서 약 10초(첫 회는 모델 내려받기 포함).
- 실패 처리: AI 다운로드가 막히면 깊이 없이 색·질감만, 분석 모듈 자체가 안 되면 `fx: {}`(움직임 없음)로 저장.
- 확인: 단위 테스트 16개(+ 갤러리 검사·저장 5개), 관리자 화면 업로드→분석→저장(가짜 GitHub)→살아난 그림 뷰어에서 물결·입체 움직임을 프레임 차이로 확인.
- 실제 그림 8점에서 본 결과: 플라밍고 = 물 흐름 + 반영 물결, 해바라기·고릴라 = 살랑임 + 반짝임, 침팬지의 노란 벽·곰 인형의 베이지 배경은 움직이지 않음.
